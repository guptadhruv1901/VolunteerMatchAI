# Architecture

The backend is organized into `db`, `models`, `schemas`, `crud`, `services`, and a provider-neutral `ai` adapter. Recommendations are generated by a deterministic catalogue/ranker with hard constraints for cause, duration, energy, participation mode, environment, equipment, accessibility, and completion history. If no item satisfies hard constraints, the API returns a no-match response rather than inventing a match.

SQLite persists profiles, daily contexts, completion records, and recommendation history. The frontend is a React Router single-page app with explicit loading, error, and empty states. It calls the backend through the centralized `src/lib/api.js` service.

Core endpoints:

- `GET /api/health`
- `GET/POST/PATCH/PUT/DELETE /api/profiles`
- `GET /api/contexts`
- `POST /api/profiles/{id}/contexts`
- `POST /api/recommendations`
- `GET /api/recommendations/{id}`
- `GET/POST /api/recommendations/{id}/alternatives`
- `POST /api/recommendations/{id}/completion`
- `POST /api/completions`
- `GET /api/history/{profile_id}`
- `GET /api/profiles/{id}/history` (completion totals plus recommendation/completion activity)
