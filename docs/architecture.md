# Architecture

The backend is organized into `db`, `models`, `schemas`, `crud`, `services`, and a provider-neutral `ai` adapter. Recommendations are generated by a deterministic catalogue/ranker with hard constraints for cause, availability, location, accessibility, and capacity. If no item satisfies hard constraints, the API returns a no-match response and ranked alternatives rather than inventing a match.

SQLite persists profiles, completion records, and recommendation history. The frontend is a React Router single-page app with explicit loading, error, and empty states. It calls the API through `src/lib/api.js`.

Core endpoints:

- `GET /api/health`
- `GET/POST/PATCH/DELETE /api/profiles`
- `GET /api/contexts`
- `POST /api/recommendations`
- `GET /api/recommendations/{id}/alternatives`
- `POST /api/completions`
- `GET /api/history/{profile_id}`
